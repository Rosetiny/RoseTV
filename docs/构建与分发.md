# 构建与分发

## 当前本机构建

需要 Windows、Python 3.9+、`requirements.txt` 中的依赖、Node.js（离线前端检查），以及 Windows .NET Framework C# 编译器。

```powershell
python -m unittest discover -s tools -p "test_*.py" -q
node source/tests/performance.mjs
python tools/build_local.py
```

构建脚本验证原始程序 SHA-256、逐一验证嵌入资源的 Brotli 内容和位置、检查新资源长度，再生成 `build/rosetv-native.exe`。原生机器代码保持原样；同时编译 `tools/Launcher.cs` 为 `build/RoseTV.exe`。公开仓库提供 `vendor/rosetv-native-base.br`，没有本机备份也可构建；首次构建自动生成本机密钥。

关闭运行中的 RoseTV 后部署这两个文件。更改 `source/public/js/rosetv.js` 和 `source/public/css/rosetv.css` 会通过本地服务加载，嵌入脚本的变更则需要重新构建。正式运行不启用调试端口。

## 目录迁移

程序目录已统一为 `RoseTV-App`。本机浏览器档案路径由配置保留，不复制大体积资料，也不清空登录、收藏和历史。缓存目录若在项目内部，随目录迁移更新配置。

## 发给其他人

不需要上传 GitHub。当前 `App/RoseTV.exe` 是启动器，单发这个文件无法独立运行。完整发行包还需附带本地服务、前端资产、原生窗口和经过测试的 Python 运行时。

启动器支持相对路径 `runtime/pythonw.exe`，为后续打包留出明确位置；当前目录没有捆绑这一运行时。不要把开发者机器的 `tools/bridge-config.json`、`provider-session.bin`、浏览器档案、缓存、观看记录或配置导出文件打包进去。接收者应生成自己的密钥和档案。

`source/BUILDING.md` 指向本文。上游 Rust / Tauri 原生重编译与当前已验证的嵌入资源构建是不同流程，不能把上游 CI 成功当成本发行包已通过测试。
